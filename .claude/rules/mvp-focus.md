# Rule: MVP focus

Applies to every task, analysis, plan and skill in this repo.

1. **Tag scope first.** Every feature, requirement, screen or task gets one tag before any work:
   `MVP` (Phase 1) · `P2` (Phase 2) · `OUT` (excluded by the quote) · `OPEN` (scope unclear; see
   `_comparison.md`). The scope table is in `CLAUDE.md`.
2. **MVP first.** Do `MVP` work in full depth. `P2` gets enough to avoid painting the MVP into a corner,
   such as a data field or a hook point, never a full design. `OUT` is listed under "Post-MVP"
   and not designed further. `OPEN` is raised as a question to the user, not decided.
3. **Smallest thing that delivers the MVP outcome.** The outcome is: Leap Up creates a project, invites
   the client, shares files and reviews video with them, end to end. Prefer the simpler option when it
   still achieves that, and say what was deferred.
4. **Wireframe ≠ scope.** The Miro board shows 8 screens. Only Login, Project Files and Video Review are
   MVP. A screen being designed doesn't put it in scope; the quote does.
5. **Flag scope creep.** If a request would add `P2`/`OUT` work to the MVP, say so in one line with the
   phase it belongs to, then ask or proceed as the user decides.
6. **Trace to sources.** Scope claims cite the quote (`bao-gia-leapup-mvp.md`) or the board
   (`leapup-website-miro-board.md`, `Lnnn`). No source, no scope.
