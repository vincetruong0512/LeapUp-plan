# US-002: See only my assigned projects

## User Story

As a Client, I want to see only the projects I am assigned to, so that my content and other clients' content stay private.

## Context

"Only assigned project content is visible." (L146); "Access is project-specific." (L170). Roles Admin / Leap Up member / Client (FR-auth-access-010).
Revised 2026-11-22 after the MVP review (QA-1, QA-19, SBA-4): one access-refusal AC per surface, a two-client leak
check behind SC-auth-access-01, and the Admin case marked blocked.

## Acceptance Criteria

### AC-001 — Assigned projects only

- **Type:** permission
- **Covers:** FR-auth-access-006 / BR-auth-access-002
- **Screen:** landing

```gherkin
Scenario Outline: each role sees only assigned projects
Given a <role> user is assigned to project "711" and not to "Grab Transport"
When the user signs in
Then "711" is listed
And "Grab Transport" is not listed

Examples:
  | role           |
  | Client         |
  | Leap Up member |
```

### AC-002 — Direct access refused, per surface

- **Type:** permission
- **Covers:** FR-auth-access-009
- **Screen:** not-assigned
- **Error code:** E-auth-access-003

```gherkin
Scenario Outline: a non-member is refused
Given client A is signed in and not assigned to project "Grab Transport"
When client A <action> of "Grab Transport" by a copied link or direct request
Then no content of "Grab Transport" is returned
And E-auth-access-003 is shown (wording and screen TBD)

Examples:
  | action                                  |
  | opens the project page                  |
  | downloads a file                        |
  | plays a video                           |
  | adds a comment to a video               |
  | marks a comment Resolved                |
  | opens the round change log              |
```

### AC-002b — Signed-out request refused

- **Type:** permission
- **Covers:** FR-auth-access-009
- **Screen:** login

```gherkin
Given nobody is signed in
When a project page, file or video link of "711" is opened
Then no content is returned
And the Login screen is shown
```

### AC-002c — Two-client leak check

- **Type:** permission (acceptance test for SC-auth-access-01)
- **Covers:** FR-auth-access-006, FR-auth-access-009

```gherkin
Given client A is assigned only to "711" and client B only to "Grab Transport"
When each client opens every page, file and video link of the other client's project
Then every request is refused
And the number of leaks is 0
```

### AC-003 — Admin sees all

- **Type:** permission · **blocked by spec OQ-10** (whether Admin sees all projects is not decided)
- **Covers:** FR-auth-access-006, 010
- **Screen:** landing

```gherkin
Given a user with role Admin
When the user signs in
Then {the projects decided in OQ-10} are listed
```

### AC-004 — No projects

- **Type:** error-path
- **Covers:** FR-auth-access-008
- **Screen:** landing-empty
- **Error code:** E-auth-access-004

```gherkin
Given a client with no assigned project
When the client signs in
Then no project is listed and E-auth-access-004 is shown (wording TBD)
```

### AC-005 — One User ID, several projects

- **Type:** business-rule
- **Covers:** FR-auth-access-006 / BR-auth-access-003

```gherkin
Given client A has one User ID and is assigned to projects "711" and "Grab Transport"
When client A signs in
Then both projects are listed
```

### AC-006 — Role is per project

- **Type:** business-rule · **blocked by spec OQ-10** (can one person hold different roles on different projects)
- **Covers:** FR-auth-access-010

```gherkin
Given a user assigned to project "711" with role {role decided in OQ-10}
When the user opens project "711"
Then the user has the rights of that role in "711" only
```
